# Intent: 브라우저 클릭 CSS 수정의 소스 코드 반영 (프레임워크 무관 DOM→소스 매핑)

## 문제 (Problem)
- React 등 프레임워크로 구현한 웹 화면의 스타일을 고치려면, 브라우저에서 본 요소가 소스의 어느 파일·컴포넌트·스타일 선언인지 개발자가 직접 찾아 수정해야 한다.
- 브라우저에서 요소를 클릭해 CSS를 바꾸는 도구(VisBug 등)의 수정은 DOM에만 머물러 소스 코드에 남지 않는다.
- 빌드된 결과물의 DOM에서는 원본 소스 위치를 찾기 어렵다. 사용자는 "리액트 빌드되고서도 DOM에서 잘 찾아야" 한다고 명시했다.
- 영향 대상: 프레임워크 기반 웹을 개발하며 AI 에이전트(서브에이전트 포함)로 코드를 수정하는 프런트엔드 개발자(요청자 본인).

## 제안 결과 (Proposed outcome)
- 사용자가 크롬에서 실행 중인 웹 페이지의 요소를 클릭해 CSS를 수정하면, AI 에이전트(또는 서브에이전트)가 해당 요소의 소스 위치를 찾아 소스 코드에 그 수정을 반영한다.
- 클릭한 DOM 요소에서 소스 위치(파일·컴포넌트·스타일 선언)를 찾는 동작이 React에 한정되지 않고 Vue·Angular 등 웹 프레임워크 전반에서 성립한다.
- 빌드된 React 앱의 DOM에서도 대상 소스를 찾을 수 있다(지원 빌드 범위는 미해결 질문 2의 답변으로 확정).
- 간격 보기: 요소에 마우스를 올리면 크기와 padding, gap이 보이고, 기준 요소를 고정하면 다른 요소까지의 거리가 보인다(개발자 도구를 열지 않고 확인). CSS 수정 전 현재 값을 확인하는 용도다(D-03).

## 영향 사용자 및 시스템 (Affected users and systems)
- 사용자: 프런트엔드 개발자(요청자). 디자이너 등 비개발 역할 포함 여부는 미확정.
- 브라우저: Chrome(사용자가 "크롬웹사이트"로 지정).
- 대상 앱: React, Vue, Angular 및 그 외 웹 프레임워크로 구현된 웹 앱.
- 연동 주체: AI 에이전트·서브에이전트(구체 제품·연결 방식은 미해결 질문 3).
- 참고 도구(사용자 언급): VisBug 크롬 익스텐션, locator.js(LocatorJS), 웍스피어(잡코리아) 기술블로그 글 "피그마 대신 코드로 디자인하면 어떨까?"(강태완).
- 본 저장소(DOMirror): 커밋 0건의 빈 저장소이며 기존 코드·모듈 없음(신규 구현 대상).

## 제약 (Constraints)
- 프레임워크 범용성: React 전용 설계 금지. Vue·Angular 등으로 확장 가능한 매핑 구조여야 한다(사용자 명시).
- 빌드 산출물 대응: 빌드 후 DOM에서의 소스 탐색이 요구에 포함된다. 단 웹 검색으로 확인한 범위에서 LocatorJS는 React Fiber의 `_debugSource`(Babel `@babel/plugin-transform-react-jsx-source`, 개발 환경용) 또는 `data-locatorjs="경로:라인:컬럼"` 속성에 의존하며 지원 대상은 React·Preact·SolidJS로 기재되어 있다. 즉 참고 도구의 방식은 그대로는 Vue·Angular·프로덕션 빌드 요구를 충족하지 못할 수 있다(가정, spec 단계 검증 필요).
- 프로덕션 빌드에서의 매핑 가능성(소스맵·빌드타임 속성 주입·휴리스틱 중 무엇이 필요한지)은 미검증이다(미해결 질문 2).
